# Research Bridge Playbook

## What

The research bridge connects the Python `tradingagents` multi-agent analysis
pipeline to the TypeScript CLI's contingency buylist. It runs the full LLM
analysis for a ticker, then extracts the pipeline-generated `entry_price`,
`stop_loss`, `position_sizing`, and `price_target` from the saved state JSON.

## Why

The Python pipeline already generates fair value estimates via structured
Pydantic output (`TraderProposal.entry_price`, `PortfolioDecision.price_target`).
These numbers are buried in markdown inside `~/.tradingagents/logs/{TICKER}/`.
The bridge surfaces them and writes them to the watchlist table where the
buylist command can use them.

## Usage

```bash
# Run analysis and show extracted values (does not write to watchlist)
trading research AAPL
just research AAPL

# Run analysis and write entry_price → watchlist.fair_value
trading research AAPL --write
just research AAPL --write

# Run with more debate rounds
trading research AAPL --debates 2
```

## What Gets Extracted

| Field | Source | Optional? | Used For |
|-------|--------|-----------|----------|
| `entry_price` | `TraderProposal.entry_price` | Yes | `watchlist.fair_value` |
| `stop_loss` | `TraderProposal.stop_loss` | Yes | Display only (future: exit plans) |
| `position_sizing` | `TraderProposal.position_sizing` | Yes | Display only |
| `price_target` | `PortfolioDecision.price_target` | Yes | Display only |
| `rating` | `PortfolioDecision.rating` | No | Display only |
| `action` | `TraderProposal.action` | No | Display only |

## Important: Pipeline Output Is Advisory

The LLM does not always generate an `entry_price`. The field is `Optional[float]`
in the Pydantic schema. When absent, the bridge displays "(not generated by
pipeline)" and refuses `--write`.

**The bridge does not replace human judgment.** It extracts what the pipeline
produced. You review it. You decide whether to use it. The `--write` flag is
explicit opt-in.

## Architecture

```
trading research AAPL --write
  │
  ├──► Spawns: python3 scripts/py/analyze_stream.py AAPL
  │     (runs full LangGraph pipeline: analysts → debate → trader → PM)
  │
  ├──► Reads: ~/.tradingagents/logs/AAPL/TradingAgentsStrategy_logs/
  │          full_states_log_YYYY-MM-DD.json (newest)
  │
  ├──► Parses: entry_price, stop_loss, position_sizing, price_target
  │     from trader_investment_decision and final_trade_decision markdown
  │
  └──► Writes: UPDATE watchlist SET fair_value = entry_price WHERE ticker = AAPL
```

## Files

| File | Role |
|------|------|
| `src/cli/commands/research.ts` | Bridge command implementation |
| `scripts/py/analyze_stream.py` | Python pipeline entry point (unchanged) |
| `~/.tradingagents/logs/{TICKER}/full_states_log_*.json` | Pipeline state output |
| `src/server/lib/schema.sql` | watchlist table (fair_value, max_position_gbp) |

## No Python Changes

Per AGENTS.md: "Never fork or modify tradingagents/ core agent logic unless
fixing a bug." The bridge reads the existing state JSON. It does not modify
the Python pipeline, the schemas, or the agent prompts.

## Future Extensions
