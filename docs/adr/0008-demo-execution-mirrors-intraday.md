# Demo 账户：跟随日内信号在 OKX 模拟盘真实下单，对账优先

在两个模拟账户之外开第三个账户「demo」：独立账本（`TRADER_HOME/demo/ledger.sqlite`，复用 `Ledger` 的表）、独立锁、独立定时任务，每小时跟随日内账户当小时的信号（Long / Short / Flat，只读日内账本的 `signals` 表），用日内账户同一套仓位规则（`trader/rules.py` 加 `trader/intraday/settings.py` 的常数）按 demo 自己的净值算目标，然后把单真的发到 OKX 的模拟交易环境（同一个域名，请求带 `x-simulated-trading: 1`，用模拟盘单独的 API 密钥）。账本里记的成交价、手续费、资金费都来自交易所的应答，不再用本地的滑点和费率模型。这样日内模拟盘和 demo 每小时做同样的决策，两边成交和净值的差异就是「模拟盘的成交假设（万五手续费 + 万五滑点）是否成立」的直接证据，也是进入小资金实盘前必须有的证据。日频、日内两个验证账户的代码、常数、指纹和验证期都不动（ADR 0004）。跟日内而不是日频，是用户 2026-11-10 的决定：日内每小时都可能成交，同样的时间里能积累多得多的成交样本。

交易所侧的设置：全仓（cross）、单向持仓（net）、每个合约 3× 杠杆。全仓和模拟盘「按总净值算仓位」的模型一致；仓位规则本身最多 2× 净值（`MAX_GROSS_EXPOSURE`），3× 是第二道闸：程序算错了，超过 3× 的单会被交易所拒掉。止损挂在交易所：条件单、触发后市价、只减仓、数量是全部持仓；每小时只收紧不放松，变了就撤重挂（2026-11-13 更新，#32：改为先原地改单；改不了就先挂一张新的，读回来确认挂上之后才撤旧的，换单期间仓位一直有止损。新的挂不上时，旧单盖得住整个仓位就留着它并告警，下一次运行再换；仓位没有止损的试 3 次，仍挂不上就市价平仓并告警。止损价已被现价穿越的不再挂单，直接平仓，和模拟盘对这种止损的处理一致）。程序停了、机器睡了，止损仍在。熔断沿用 `KILL_DRAWDOWN`：触发时交易所一键平仓、撤所有条件单、账本置 halted，`python -m trader demo resume` 才解除（2026-11-13 更新，#33：先置 halted 再逐个平仓，一个合约平不掉不影响其他合约，它的止损单留着，之后每次对账再平、再告警，直到交易所里核实空仓；只撤已平合约的条件单。人可以随时用 `python -m trader demo halt` 熔断；解除改为 `demo resume --kill`，交易所里还有仓位就拒绝，不加 `--kill` 的 `demo resume` 解除的是暂停）。

对账优先：每次运行先把交易所的余额、持仓、新成交、资金费和挂着的条件单读回来写进账本，交易所是事实，账本是它的副本加我们自己的注解（止损价、成交归因）。成交按客户端订单号的前缀归因为 trade / stop / kill；客户端订单号由小时和币决定，同一小时重跑不会重复下单（交易所拒绝重复的客户端订单号，我们把那个拒绝读作“已下过”）。账本与交易所对不上——有持仓没止损单、有止损单没持仓、数量不等——先修复能修的（补挂或撤掉止损单），修不了的告警并跳过本小时的交易，不在对不上账的状态下加仓（2026-11-13 更新，#32：有持仓没止损单的，补挂试 3 次，仍挂不上就市价平仓并告警）。（2026-11-13 更新，#34：程序解释不了的变化不再只跳过一个小时，而是让账户暂停，由人解除：不是程序下的成交、成交和资金费解释不了的余额变动、到下一次整点对账还解释不了的持仓。暂停不平仓，仓位和止损原样留着，见 ADR 0010。）

这一期只开模拟盘：私有接口客户端（`trader/okx_private.py`）只接受 `simulated=True`，实盘路径在代码里不存在，模拟盘的密钥没有任何配置能让它碰到真钱。密钥只从 `.env` 读（`TRADER_OKX_DEMO_KEY / TRADER_OKX_DEMO_SECRET / TRADER_OKX_DEMO_PASSPHRASE`），实盘将来用另一组变量名；日志、异常文本、`repr` 里不出现密钥和签名。开实盘要另写 ADR，前提是 demo 和日内模拟并行跑满至少 7 个交易日、逐笔对照的报告入库（Issue #22），且验证期的结论支持（`docs/roadmap.md` 一期退出条件）。2026-11-13 更新：用户决定不等这两个前提，实盘账户的设计见 ADR 0010。

## Consequences

- 看板仍然只读（ADR 0005）：它展示的是 demo 账本里最近一次对账写下的快照，不调交易所私有接口；解除熔断、手动平仓仍是 CLI 的事。
- demo 的本金是模拟账户当时的 USDT 余额（`demo init` 读回来），要求当时无持仓；和模拟盘的 10,000 不同时比百分比。
- 日内任务在整点 03 分，demo 在整点 10 分，最多等 15 分钟让日内账户决完这个小时（每 60 s 看一次 `decided_hour`）；日内这个小时没决（失败或停电），demo 就不交易，持仓靠交易所里的止损托底。天然有几分钟的滑点差：日内模拟按 03 分前后的最新价成交，demo 按自己下单那一刻的市价成交，对照报告要把这段时间差单独列出来。
- 止损在交易所触发后，账本要到下一次对账才知道；小时内的资金费也是。这是可接受的滞后，因为止损本身不依赖我们的进程。
- 成交和账单的时间戳是交易所的时钟，可能比我们的快几秒（2026-11-10 mini 慢 1～3 秒，对账窗口以本机“现在”封顶时切掉了两笔刚等到的成交）：对账的读取窗口向后放宽 CLOCK_SKEW_MS，往前重叠 SYNC_OVERLAP_MS，按 billId 去重。近三天的成交读 OKX 的三天接口（为最近成交设计、限流宽），更早的才读三个月历史。“成交能解释的仓位”是账本里全部已记成交的累计和（账户从空仓开始），不是“上次仓位 + 新成交”：迟到的成交到了就抵消之前按交易所记下的仓位，不会叠加成第二次“不一致”。
- 模拟交易的成交是撮合引擎按真实行情模拟的，深度不等于实盘；它能验证流程、幂等、对账和数量精度，对滑点只是下界。小资金实盘才是滑点的答案。
- OKX 模拟账户要是合约模式（以前叫单币种保证金）或跨币种保证金才能交易合约，API 只勾“交易”权限且要覆盖加密货币/永续合约；`python -m trader demo check` 把这些读出来给人看。交易权限的产品范围在 `account/config` 里看不到（不覆盖加密货币的 key 也显示 `trade`，到下单才报 50123），所以 check 和 init 都先探一次：撤一张不可能存在的订单，网关拒绝（50xxx）就是权限不足，返回“订单不存在”（51400）就是能下单；不产生订单，不改设置。OKX 的下单预检接口不能用作这个探针：它只对跨币种/组合保证金开放，合约模式下一律返回 51010。

## Considered Options

- 跟日频账户：是将来实盘的那套，每天最多三笔单、对账简单；但样本太少，几周也说不清成交假设对不对。用户选了日内。
- 把日内模拟账户直接换成交易所执行：改动落在验证中的账户上，违反 ADR 0004，也失去了模拟与真实成交的对照。
- 止损只在本地算、到价再下市价单：每分钟都要跑且依赖机器在线；mini 睡着的那几小时（Issue #3）就是裸奔。交易所侧止损不依赖我们的进程。
- 逐仓保证金：每个仓位单独爆仓、单独补保证金，和模拟盘按总净值算仓位的模型不一致，多一套逻辑。
- 复制日内模拟的成交数量而不是重算目标：两边本金和净值路径不同，照抄数量会让风险比例漂移；重算才是“同一套决策过程”。
