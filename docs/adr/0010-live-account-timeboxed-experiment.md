# 实盘账户：不等验证期结论，先用小额资金跑一次带期限的实验

ADR 0008 给实盘定了两个前提：demo 和日内账户并行跑满至少 7 个交易日、逐笔对照的报告入库（Issue #22），并且验证期的结论支持。用户 2026-11-13（北京时间）决定把两个前提都放掉，现在就开第四个账户「live」：用用户自己的钱，在 OKX 正式环境交易同一个自选池的永续合约。它是一次带期限的小额实验，要回答的是碰真钱的这条链路对不对：正式环境的费率和成交、账户规则、密钥、对账、无人值守。Signal 能不能赚钱不由它回答，那仍然是验证期的事。替别人操作资金仍是 roadmap 阶段 3 的事，不在这次范围内。术语 Live、Signal、Pause、Shadow Run 见 `CONTEXT.md`。

## 规则

- **钱。** 在 OKX 全球站主账户下新建一个只给这套系统用的子账户，先转入 500 USDT。这套系统能碰的真钱上限是 2,000 USDT。运行期间不出入金；剩下的额度要等到期结论支持，并且出入金记账已经完成（Issue #40），才转入。
- **期限。** 跑到 2026-12-05，即验证期最早出结论的日子。期间熔断一次就不再解除。到期出一份 live、demo、日内模拟盘三方逐笔对照的报告，和验证期结论一起决定继续、改跟 Rating 还是停；决定另写 ADR（Issue #43）。
- **跟 Signal，规则照搬 demo。** 每小时跟随日内账户当小时的 Signal，仓位规则、常数和交易所设置（全仓、单向持仓、3 倍杠杆、交易所侧止损）与 ADR 0008 相同，这样 live 和 demo 的差别只来自成交环境。跟 Rating 的交易所执行器以后另做。
- **两个绝对上限，只属于 live。** 账户净值超过 2,000 USDT 就暂停；单笔订单名义超过 4,000 USDT 就拒单。它们防的是算错和误转入：现有代码没有任何绝对金额上限，账户里有多少 USDT 就按多少算仓位。
- **两个停止状态，都只能由人解除。** 熔断（Kill Switch）是全部平仓并停止，在回撤到 `KILL_DRAWDOWN` 时自动进入，人也可以用“停止并平仓”命令触发。暂停（Pause）是不再下新单，现有仓位和交易所里的止损单原样保留，在下列情况进入：出现不是程序下的成交（包括强平）；余额的变化不能由成交、手续费、资金费解释；账本推算的持仓与交易所不一致。live 另外在两种情况下暂停：代码或 Signal 的指纹（模型、提示词、自选池）变了；净值超过上限。暂停期间不自动熔断：回撤到阈值时只告警，人仍然可以用命令触发熔断。
- **异常引起的暂停对 demo 同样生效。** 两个账户共用一份执行器，演示环境是这条路径唯一能演练的地方。
- **影子运行和解锁。** live 账户建立时就处于暂停。从建立到第一次解除暂停是影子运行（Shadow Run）：每小时照常对账，记录本该下的单，不下单，用只读权限的密钥就够。第一次解除暂停称为解锁，之后全自动下单。
- **密钥。** 建在子账户下，只勾交易、不勾提币，绑定 mini 的固定出口 IP。只放在 mini 上一个单独的文件里，只有 live 的任务读取；不进 `.env`，不同步到别的机器。
- **心跳。** mini 上的告警都从 mini 自己发出，任务不跑时发不出来。live 任务每小时成功后请求一次外部监控服务的地址，超过 2 小时没收到，由那个服务通知用户。

## 解锁的条件和工作分档

解锁的条件是第 1、2 档的代码合入，加上用户侧两件事：mini 关闭睡眠（Issue #3），mini 上设 `TRADER_WEB_TOKEN`。在演示环境上的演练要做，但不卡解锁（#42）。#22 的报告照常出，不再是前提。

- 第 1 档，影子运行之前：正式环境的客户端开关、单独的密钥文件和只读检查（#30）；live 账户、生来暂停的影子运行、带账户名的告警、心跳（#31）。
- 第 2 档，解锁之前：止损单更新期间不留空窗，成交后挂不上止损就平仓（#32）；熔断先写状态、逐个仓位容错、平后核实，加“停止并平仓”命令，余额读不到按出错处理（#33）；暂停状态和上面的触发条件、两个绝对上限（#34）。
- 第 3 档，解锁之后、实验期间：告警改进（#36）、对不上账的修复命令（#37）、备份包含 demo 和 live 的账本（#38）、下单前的输入检查和顶格反手（#39）、出入金记账（#40）、看板显示 live 账户（#41）。
- 用户侧的事项列在 #35。

## Consequences

- 没有证据说明 Signal 有预测力：线上信号的回放是 +5.23%（3.4 天），历史行情上的重跑是 −12.12%（14 天），样本都太小（见 `docs/reports/`）。按重跑那 14 天的换手（约 50 倍本金）和万五的费率，手续费每两周约为本金的 2.5%，500 USDT 对应约 12.5 USDT。这笔钱按“可能亏完”来算。
- Signal 断供（LLM 中转故障、代理不通、mini 不在线）时系统不决策，仓位只靠交易所里的止损单，没有最长持仓时间。
- 止损按最新成交价触发、触发后市价成交，跳空时没有价格保证。设计按“最坏亏光子账户里的钱，主账户不受影响”来做。这一点 #30 查了 OKX 的文档，没有找到明文保证，只有间接的说法（子账户有独立的用户 ID，帮助中心说可以用它“独立控制风险”）；穿仓之后平台会不会向同一用户的其他账户追偿，要看服务条款或问客服，入金之前由用户确认（#35）。
- 账户有被平台按服务条款限制的可能。子账户里的钱按“可能拿不回来”来算，所以上限定在 2,000 USDT。
- 第 3 档的缺陷在实验期间存在。其中两条会直接影响对照和判断：顶格仓位的反手会被拒单，live 和 demo 会同样偏离日内模拟盘；止损成交要到第二天的日报才通知。
- ADR 0008 写的“实盘路径在代码里不存在”从 #30 合入起不再成立。之后的保证是：正式环境的请求只有 live 的命令组能发出，用的是单独文件里的密钥；demo 的密钥仍然只在演示环境有效。
- ADR 0008 里“对不上账就跳过本小时”改为进入暂停、等人解除，demo 也一样。部署之后，demo 出一次异常就会停到有人执行 `demo resume` 为止，#22 的报告要记下这个时间点。
- 看板仍然只读（ADR 0005）：解除暂停和熔断、停止并平仓都是命令行的事，手机经 Tailscale SSH 执行。ADR 0007 说改模型“不会产生不可逆的成交”，在 live 上靠“指纹一变就暂停”保持成立；`TRADER_WEB_TOKEN` 成为解锁条件，也是因为这个写入口。
- live 和 demo 共用 mini 上的一份代码目录。每次部署改到 `trader/`，live 都会暂停一次，要人看过 demo 之后手动解除。
- 几个 OKX 的事实。#30 对着官方文档核实了的：正式环境的 REST 域名是 `https://openapi.okx.com`，`https://www.okx.com` 继续可用；子账户不能提币，子账户的交易 key 默认能把钱划回主账户、不能从主账户拿钱；没有绑定 IP 的交易 key 14 天不用会失效。要用真实密钥在 mini 上实测的（#35）：带签名的请求从 mini 的网络到不到得了 `openapi.okx.com`、账户的实际费率、只读 key 被权限探针拒绝的错误码。还没核实的：两张止损单能否同时挂着、重复订单号的错误码（#42）。2026-11-13 更新：#32 合入的换单先原地改单，只有改不了单或反手时才先挂第二张、确认挂上再撤旧的；交易所要是不让两张并存，这两种情况下仓位会被平掉（旧单盖得住整个仓位时留着它）。文档里写的止损单重复订单号的错误码是 51065，代码不依赖它。合约规格已经核对过：公开接口读的本来就是正式环境的值，BTC 的最小价格单位在正式环境是 0.1，在演示环境是 0.01，其余规格两边相同。
- 2026-11-13 更新（#31 合入）：live 和 demo 用同一个执行器（`trader/demo/`），按账户的 `Profile` 区分；live 的定义和解锁开关在 `trader/live/account.py`。开关 `UNLOCK_OPEN` 写在代码里、默认关，打开它要改代码（#34）；关着时 `live resume` 不读密钥、不问交易所就拒绝，打开后还要求账户处于暂停、没有熔断、交易权限确立。暂停的账户拿到的交易所客户端是只读的：不设置账户、不挂改止损、不下单、不熔断，没有止损的仓位和回撤到线都只告警。`live init` 只读建账，要求子账户空仓、没有条件单，确认是主账户的 key 就拒绝。每条 Telegram 消息前面带账户名（【demo】、【live】），demo 的消息格式随之变了。心跳只在每小时任务正常结束后发，任务出错、没建账、密钥文件有问题都不发；地址不进日志。live 熔断后的告警现在写着运行 `live resume` 恢复，而 resume 拒绝熔断中的账户（熔断一次就不再解除）；这条告警要解锁之后才可能出现，#33 加熔断相关的命令时一并改。
- 2026-11-13 更新（#33 合入）：熔断先在账本里置 halted、记事件，再逐个合约平仓：一个合约平不掉不影响其他合约，它的止损单留着，之后每次对账再平、再告警，交易所里核实空仓后提醒一次；熔断的告警随对账结果发出，不受失败告警的限频。“停止并平仓”命令是 `python -m trader live halt`（demo 是 `demo halt`），先确认，加 `--yes` 不问；暂停中也能用，平仓走不受暂停限制的客户端，这是“暂停的账户不改交易所”唯一的例外，只能由人触发。live 的熔断不解除：`live resume --kill` 一律拒绝，告警和日报写“按 ADR 0010，live 熔断一次就不再解除，实验到此结束”，上一条说的告警文字已改；demo 解除熔断改为 `demo resume --kill`，不加 `--kill` 的 `demo resume` 解除暂停。余额读不到（应答里没有 USDT，或缺权益、钱包）按出错处理：这次运行失败并告警，不入账，`live init` 拒绝建账。
- 2026-11-13 更新（#34 合入）：暂停带原因：账本记下每个原因和它进入的时间，同一个原因只进一次、只告警一次，日报每天列出原因和解除命令，看板的执行对账显示 demo 的暂停和原因。触发都在对账里判断，demo 和 live 相同：不是程序下的成交（含强平、自动减仓）；余额的变动读 OKX 的账单（`/api/v5/account/bills-archive`），成交（类型 2）和资金费（类型 8）以外的变动（划转等）算一个原因，它在的时候净值不算数：峰值不动、不判熔断；账本推算的持仓与交易所不一致，第一次是问题（这个小时不下单），30 分钟后（`MISMATCH_GRACE_MS`，即下一次整点运行）还不一致才暂停，晚到的成交（#26）有一个小时补上。live 的指纹是 `trader/` 下全部 Python 文件的摘要，加日内账本记下的 Signal 指纹（版本、模型、研究代码、自选池）；每小时运行开始时和拿到这个小时的信号之后各比一次，变了就暂停，每个变化一个原因，新指纹在比对时记下。净值超过 2,000 USDT 就暂停；4,000 USDT 的单笔上限按这一单的变动算名义，超过就拒单并告警，和总敞口的拒单走同一条路径。`demo resume` 和 `live resume` 先在锁里对一次账（live 先比指纹）：对账发现新的原因、会马上再暂停的情况还在（持仓不一致、净值超限）、或者没有熔断而回撤已到 `KILL_DRAWDOWN`（解除后一有持仓就会熔断；回撤若来自转出的钱，#40 之前只能转回），都不解除，并说明原因。`live resume` 另要求设了 `TRADER_WEB_TOKEN`。`UNLOCK_OPEN` 已打开，解锁的用户侧条件（mini 关闭睡眠 #3、#35 的交易 key、部署）由人把关。部署之后：demo 遇到上面的情况会停在暂停，直到 `demo resume`；每次部署改了 `trader/` 都会让 live 暂停一次，部署后要运行 `live resume`。反手的一笔变动是持仓名义的两倍，持仓名义超过 2,000 USDT 时反手会被单笔上限拒掉，#39 处理顶格反手时一并考虑。

## Considered Options

- 按 ADR 0008 原文等两个前提：最早 12 月才能下第一笔真钱单。用户不选。
- 把两个前提拆开：#22 通过并修完必修的缺陷后先上小额，追加资金等验证期结论。这是讨论时提出的建议，理由是验证期回答策略、小额实盘回答链路，两者互不依赖，而 #22 是这套执行器唯一的验收。用户选了两个都放掉，并把解锁条件定为只有第 1、2 档的代码和两件用户侧的事。反对的理由记在这里：信号的证据不足；第一笔真钱单会是这条路径第一次在正式环境被检验。实际上第 1、2 档做完时 #22 也已跑满 7 天，省下的主要是等验证期结论的三周多。
- 先写跟 Rating 的执行器再上实盘：这是文档里原定要上实盘的那条决策流，换手和杠杆都低得多；但要多写一套执行器，而且没有在演示环境上验证过。以后另做。
- 每笔单先在 Telegram 确认：每小时决策、全天运行，逐单确认做不到。
- 只有一个停止状态，任何异常都全部平仓：人手动动仓位是想接管，程序再把剩下的也平掉，违背这个意图。
- 暂停期间熔断照常生效，余额变化引起的暂停除外：多一层保护，但暂停期间不开新仓，亏损最多是现有仓位各自打到止损，熔断能多挡的很少；因余额变化暂停时净值的基准已经不可信；规则还多一个例外。代价是人长时间不处理时，没有组合层面的止损。
- live 用单独的代码目录、固定在某个提交：更严，但要多维护一套部署；指纹变化就暂停，已经保证每次变更之后有一次人的确认。
- live 用更保守的常数：规则一变就没法和 demo 对照；限制风险的是入金的数额。
- 密钥和 demo 一样放进 `.env`：`.env` 被所有命令和看板进程加载，还会同步到笔记本。
- 不加心跳：有交易所止损托底，亏不了多少；但这次要验证的正是无人值守这条链路，静默停几个小时会污染结论。
