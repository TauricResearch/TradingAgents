# 研判日取运行时刻所在 UTC 日的前一天

每天 00:00 UTC 之后运行，`trade_date` 填前一个 UTC 日，进程固定在 UTC 时区。原因是 `tradingagents` 按"日期 ≤ trade_date"过滤行情，不区分当天的日线有没有收盘。填当天的话，会混进刚开盘、成交量接近 0 的 K 线，扭曲 ATR、volume 等指标。另外，项目判断"今天"和划分缓存日界都用本机日期，进程固定在 UTC 后，这两者才和加密货币的日线边界一致。

## Consequences

- 这次运行会被当作历史运行，Polymarket 和实时概况被屏蔽。这对加密货币影响不大。
- memory 结算的入场价比模拟盘的实际成交晚约 24 小时。这只影响 PM 读到的反思，不影响按账本计算的策略表现。
- 2026-11-16 更新（#53）：Yahoo 在 UTC 零点后先去掉刚结束那天的日线，几小时后才重新给出（11-14 实测在 06:50–07:20 UTC 之间，BTC/ETH/SOL 相同），00:05 的研判因此只看到研判日前一天为止的日线。现在研判前先问 Yahoo 研判日的日线出了没有（问不到按没出），没出的币照常研判；daily 每小时 :05 复查到 12:05 UTC，日线出来后用一个清空的新数据缓存重跑，重跑的评级取代第一次的（记录、memory log 里待结算的那条、模拟盘用的评级）。模拟盘等所有币都用上研判日的日线再执行、发日报，到 12:00 UTC 还没等到就告警，按已有的评级执行。研判日的定义不变；模拟盘的执行时刻从约 00:15 推迟到研判日的日线出来、重跑完之后。这是验证期内的 bug 修复（ADR 0004），没改 `tradingagents/`，研判指纹不变。

## Considered Options

- 改数据层，丢弃未收盘的 K 线：与 0001 冲突。
