# Web 层只读账本，写操作只走 trader/ 的任务

看板和 API 放在仓库顶层的 `web/`（FastAPI 后端、React 前端），以只读方式打开账本（SQLite `mode=ro`），只复用 `trader/` 的读函数和绩效计算，不写账本、不下单、不解除熔断。原因是账户的每一次变动都要在 `trader/` 的文件锁和单事务里完成，多一个写入口就多一处并发和幂等的风险；而且产品的终点是替用户操作实盘资金，这条边界从第一天就要立住：改变账户状态的操作必须经过认证和审计，那是另一个模块的事，不是看板顺手加个按钮。API 的路径从一开始就带 `account_id`，虽然现在只有一个模拟盘账户。

## Consequences

- 看板不能解除熔断或手动触发研判，这些仍用 `python -m trader resume` 和 `launchctl kickstart`。
- 加写操作时要新开模块，带登录、二次确认和审计日志，并且通过 `trader/` 现有的 `locked()` 和 `Paper` 方法执行。

## Considered Options

- Streamlit 单文件看板：最快，但以后做产品要推倒重来。
- 看板直接带解除熔断、手动研判按钮：方便，但在没有认证的本地页面上暴露会动账户的操作。
