Test-driven clarifications documented
-------------------------------------
- The 20% concentration cap applies to position-increasing BUY orders. SELL is
  risk-reducing and exempt from the concentration cap, while the 10% notional cap
  still applies to both BUY and SELL (pinned by ACT-15/FND-23 and FND-22).
- A stale caller snapshot whose proposal version matches the DB is
  REJECTED/STALE_PORTFOLIO. A proposal that loses a concurrent portfolio-version
  race returns the distinct status STALE_PORTFOLIO; no ledger write (pinned by
  ATM-01 vs ATM-07/ATM-09).
- HOLD requires a valid evidence pack; claims are optional because no order is
  created. BUY/SELL require at least one claim with resolvable evidence.
- Exactly one outbox event per stored verdict (Phase.RISK_GATE), matching the
  duplicate/idempotency tests.

D↔E contracts.audit compatibility (E review fix)
------------------------------------------------
E's review found that the outbox payload_hash was not byte-compatible with
contracts.audit.recompute_payload_hash: the risk gate used a timestamp rendered as
``+00:00`` while Pydantic's JSON model dump (and therefore contracts.audit) renders
UTC as ``...Z``. E measured 618df15d... versus a159cae7... for the same event, so
verify_payload/replay would reject a legitimate risk_gate event.

Fix commit 6bad169:
- outbox payload_hash uses contracts.audit-compatible canonicalization: JSON with
  sorted keys and compact separators over the RunEvent fields excluding
  payload_hash, with the timestamp rendered as ``...Z``;
- the outbox stores the same ``...Z`` timestamp;
- proposal/policy/evidence canonicalization is unchanged.

Verification against E's actual contracts code (extracted from
origin/impl/FR-05-contracts-v3, since contracts are not yet on main):
- constructed contracts.events.RunEvent from the persisted outbox row;
- contracts.audit.verify_payload(event) -> OK;
- stored payload_hash == recomputed payload_hash =
  eaa25281582252eeddd22a4d581fa25b4e99c71425f78c69888e4714b13f8955.

Post-#18 re-verification: after E's contracts PR #18 merged on main (`10ee52d`),
contracts.audit is available on main. Re-ran `verify_payload` against the persisted
outbox event using main contracts: OK; stored == recomputed. The earlier

Idempotency constraint confirmation (E nuance):
- ``UNIQUE(proposal_hash)`` is intentional and single-column. proposal_hash covers
  run_id, so it is at least as strict as ``(run_id, proposal_hash)``; a cross-run
  collision would imply identical formal proposal content including the run id.
  Documented in risk-policy.md §6.
